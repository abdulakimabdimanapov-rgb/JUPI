How it plays

CROSSHAIR Permanently centered — the shot ray always passes through screen center
TARGET Red cube: after a hit it respawns at a random spot + height and drifts
SCORE Every shot counts (hit or miss) — accuracy is hits / shots, time is tracked

Player

CharacterBody3D with gravity and WASD movement relative to facing, driven by a swapable aim source that controls body yaw / head pitch. In hand mode, any open hand walks the player forward at constant speed (keyboard is ignored).

Aim Sources

Abstract interface (get_aim / handle_input / is_active / activate). Mouse source: pointer capture, sensitivity, pitch clamp, Escape toggle. Hand source: UDP packets, relative deltas with deadzone, and a baseline on pinch start so the view never jumps.

Hand Tracker

Python + MediaPipe landmarker detects up to two hands, computes pinches (with hysteresis to avoid double-shots), and streams edges and positions over UDP 127.0.0.1:37020. Auto-spawned when the game starts and killed on exit.

Aim & Score

Permanently centered crosshair; the shot ray always passes through the exact camera center. Hits / shots / accuracy / session time in the HUD. A hit respawns the target at a random spot and height tier where it drifts slowly.

Runtime Tests

Four headless test scenes (71 checks) drive the real main scene: center crosshair + raycast, left pinch = look, right pinch = exactly one shot, open hands walk.

Fallbacks

If the tracker venv, script, webcam or UDP port is unavailable, the game prints the reason and keeps running with pure mouse aiming; the status label shows starting / online / unavailable.
